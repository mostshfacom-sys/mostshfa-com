# تحسين وتصليح ومخطط تطوير بيانات العيادات

> **الغرض من هذا المستند (Prompt جاهز)**: تلخيص ما تم إصلاحه في مشروع العيادات (الخريطة/البيانات/السكربتات/قاعدة البيانات)، وتحديد مواصفات سحب البيانات المطلوبة لاستكمال بيانات العيادات بدون تكرار أخطاء الماضي، مع توصيف دقيق لحالة السكربت الحالي وأسباب فشله وخطة علاج قابلة للتنفيذ.

---

## 1) الهدف العام
- **رفع جودة بيانات العيادات** في موقع Mostshfa بحيث تشمل:
  - بيانات أساسية صحيحة (اسم، عنوان، محافظة/مدينة، هاتف)
  - بيانات غنية (صور حقيقية، ساعات عمل، تقييمات)
  - **إحداثيات دقيقة فقط** (Lat/Lng) من مصادر قابلة للتحقق (مثل Plus Codes أو Place ID)، مع تجنب أي حلول تقريبية (Centroids/Jitter).
- **إظهار العيادات على الخريطة** وإصلاح مشاكل العرض/التحميل.
- **بناء سكربت سحب resilient**:
  - يتجنب التكرار
  - يتوقف بشكل آمن عند CAPTCHA/Block
  - يستأنف من حيث توقف
  - يُسجل Logs دائمة

---

## 2) التشخيص الأساسي لمشكلة الخريطة (لماذا كانت تظهر عيادات قليلة)
- السبب الجذري: **نسبة كبيرة جدًا من العيادات لا تحتوي على Lat/Lng**.
- تمت ملاحظة أن **عدد قليل فقط من العيادات** لديه إحداثيات صحيحة، وبالتالي أي فلترة على `lat/lng not null` في API كانت تسبب ظهور “جزء صغير” على الخريطة.

---

## 3) إصلاحات الخريطة (الاستبدال + علاج أخطاء Google Embed)
### 3.1 استبدال Leaflet بخريطة Google Embed لصفحة تفاصيل العيادة
- تم استبدال خريطة Leaflet داخل صفحة تفاصيل العيادة بـ **Google Maps Embed iframe**.
- تمت معالجة خطأ: **"Place info couldn't load"** عبر تحسين صيغة رابط Embed، واستخدام query أكثر استقرارًا (اسم + عنوان) واستخدام `iwloc=addr`.

### 3.2 API ماركرز الخريطة التفاعلية
- تم تعديل `src/app/api/map/markers/route.ts` ليكون أكثر شمولاً في جلب البيانات وعدم حصر النتائج بشكل يمنع ظهور العيادات.

---

## 4) سياسة الإحداثيات (Coordinates Policy)
- المتطلب الأساسي: **عدم إدخال إحداثيات تقريبية** (مثل centroids للمدينة/المحافظة) لأنها تسبب تضليل.
- تم الاعتماد على:
  - **Plus Codes** داخل العنوان عند توفرها لاستخراج إحداثيات.
  - لاحقًا تم الاتجاه لإضافة **Google Place ID** كهوية ثابتة تمنع التكرار وتُسهل استكمال بيانات دقيقة.

## 6) مواصفات البيانات المطلوبة للسحب (Scraping Data Spec)
### 6.1 حقول أساسية (Must)
- `nameAr`
- `addressAr`
- `governorateId`, `cityId` (تعيين صحيح)
- `phone` (إن وُجد)
- `slug` (Stable)
- `status='published'`

### 6.2 حقول غنية (Should)
- `image` أو `gallery`
- `workingHours`
- `ratingAvg`, `ratingCount`
- روابط التواصل (facebook/website/whatsapp…) إن توفرت

### 6.3 حقول الموقع (Geo)
- `lat/lng` فقط إذا كانت **دقيقة وقابلة للتحقق**:
  - Plus Code داخل العنوان
  - أو مصدر مباشر موثوق

---

## 7) منع التكرار: لماذا Place ID هو الحل الصحيح
- التكرار لا يُحل “100%” بالاسم/العنوان فقط بسبب اختلاف الصياغة.
- الحل: **استخدام Google Maps Place ID كمفتاح فريد**.

### 7.1 تعديل قاعدة البيانات (تم تنفيذه على Neon بدون Reset)
- تم إضافة عمود جديد في جدول `clinics`:
  - `google_place_id` (nullable)
  - عليه **Unique index**
- تم تطبيقه بأمر SQL آمن:
  - `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`
  - `CREATE UNIQUE INDEX IF NOT EXISTS`
- **لا يوجد حذف بيانات**.

---

## 8) مواصفات السكربت resilient المطلوب (Resilient Scraper Requirements)
- **Checkpointing**:
  - حفظ progress بعد كل (مدينة/تخصص/رابط)
- **Logging دائم**:
  - ملف `scrape.log`
- **Retry Logic**:
  - Backoff وإعادة محاولة عند network/timeouts
- **Stop-on-Block**:
  - اكتشاف CAPTCHA/Unusual traffic والتوقف الآمن
- **Dedup قوي**:
  - upsert على `googlePlaceId`
  - منع أي duplicates على مستوى DB
- **Batch/Sample mode**:
  - تشغيل بعينة صغيرة (مثل 5) للتحقق على الموقع قبل السحب الشامل

## 9) مواصفات السكربت الحالي (resilient-mega-scraper.ts) + ما تم تطويره
### 9.1 ما تم إضافته/تطويره
- تحميل `DATABASE_URL` تلقائيًا من `.env` الرئيسي عند غياب `.env` في مجلد السكربت.
- Logs دائمة `scrape.log`.
- Checkpoint متقدم `checkpoint.json` (city/spec/link index).
- اكتشاف block/captcha.
- جمع روابط نتائج Google Maps عبر scrolling (بدلاً من 20 فقط) مع حدود قابلة للضبط.
- إضافة `RESET_CHECKPOINT=1` لتجاهل checkpoint بدون حذف ملفات محلية.
- إدخال `SAMPLE_LIMIT` لتجربة 5 عيادات فقط.
- إضافة استخراج معرف ثابت من رابط Google:
  - `cid` أو token `0x...:0x...` وحفظه في `googlePlaceId`.
- `upsert` على `googlePlaceId` لمنع التكرار نهائياً.

### 9.2 لماذا يوصف بأنه “فاشل حالياً” في التشغيل العملي
- التشغيل على Windows/Puppeteer قد يبدو “متجمد” بسبب:
  - بطء/تعليق Chromium أول مرة
  - أو block/CAPTCHA
  - أو إلغاء تشغيل الأمر قبل اكتماله
- لم يتم حتى الآن الحصول على Run كاملة تُخرج 5 روابط بسبب توقف/إلغاء التشغيل قبل النهاية.
